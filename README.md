# AI-Driven Autonomous Liquid Tree Monitoring and Bio-Resource Optimization System

A B.Tech project prototype exploring microalgae growth analysis, microscopy-based
cell detection, and a local dashboard for a conceptual urban photobioreactor
(“Liquid Tree”). The repository contains offline research analyses and a software
demonstration. It is not connected to a physical reactor and is not validated for
autonomous operation.

## Current capabilities

- A local Python HTTP API and browser dashboard for simulated reactor telemetry,
  illustrative historical charts, alerts, experimental recommendations, and a
  formula-based next-day growth estimate.
- A YOLOv8 Nano microscopy proof of concept that detects individual cells
  (class 0) separately from clusters/noise (class 1) on prepared CIDACC
  hemocytometer images. Ground-truth annotations are shown separately for
  comparison. Vision counts are not converted to culture density because
  experimental calibration is unavailable.
- Offline analyses of *Chlorella* growth experiments, grouped Random Forest
  baselines, growth dynamics, and published photobioreactor data.

Telemetry and historical dashboard series are simulated or illustrative. The
dashboard growth estimate is a hand-coded formula, not the offline Random Forest
and not a trained dashboard model. Recommendations are experimental suggestions,
not validated control instructions. No hardware integration, live sensing,
actuation, or validated Liquid Tree performance is claimed.

## Architecture

```text
Browser dashboard (dashboard/)
          │ HTTP / JSON
          ▼
Python standard-library server (api/server.py)
          │
          ├── API and microscopy service (api/service.py)
          ├── local YOLOv8 inference (Ultralytics + PyTorch; when files exist)
          └── simulated telemetry, formula estimate, alerts, and recommendations

Offline notebooks and analysis scripts (notebooks/, src/)
          └── research data and evaluation reports (data/, reports/)
```

The server uses Python’s built-in `http.server`; Flask is not used. Microscopy
inference additionally requires the selected checkpoint and prepared validation
images/labels. If those are absent or the model cannot load, the API reports an
unavailable/error status instead of substituting annotations for predictions.

```text

dashboard/    Static HTML, CSS, and JavaScript dashboard
data/
  raw/        Local source workbooks and microscopy data (not distributed here)
  processed/  Derived tables, frozen split metadata, and local microscopy files

src/          Preprocessing, analysis, and training scripts
tests/        Python unittest suite

```

Large or rights-unclear source data, image splits, and model binaries are excluded
by `.gitignore` and remain unchanged on the local machine. Small split manifests,
metadata, reports, source code, and notebooks are intended to remain reviewable
project artifacts.

## Data provenance and distribution

- **Hiltunen growth experiments:** the local source workbook is named
  `hiltunen_etal_chlorella_growth_biochem_data.xlsx`; project notes describe 61
  cultures across four experiments. The local documentation does not contain a
  complete bibliographic citation or a confirmed redistribution license. The
  workbook is therefore not included in a source publication package.
- **Photobioreactor data:** the project audit identifies
  `Supplementary Data Excel.xlsx` with Zenodo DOI
  [10.5281/zenodo.22065573](https://doi.org/10.5281/zenodo.22065573). The raw
  workbook remains local; check the record’s terms before redistributing it.
- **CIDACC microscopy:** local project reports describe 628 640×640 source
  images and a frozen image-level split of 438 train, 93 validation, and 95 test
  images. The small split manifest and metadata are retained. Raw images and
  prepared image/label directories are excluded because the local project
  records do not establish redistribution rights. The validation comparison
  used only the frozen validation split; it did not evaluate the test split.

No dataset is silently replaced or regenerated by these instructions. Obtain
data from its authorized source, confirm its license, and preserve the existing
split identity before restoring files locally. Derived observation CSVs are
also kept local because the source terms have not been verified; the analysis
scripts under `src/` document the project’s transformations and can recreate
derived tables from authorized local inputs. The notebooks contain saved
analysis outputs, so verify their data reuse terms before redistributing them.

## Research models and limits

### Offline Random Forest experiments

The offline scikit-learn experiments use Hiltunen culture observations and
grouped validation. The recorded basic-feature Random Forest result was
`R² = 0.928` under five-fold culture GroupKFold and `R² = 0.726` under
leave-one-experiment-out (LOEO). The transfer gap and experiment-level variation
are material limitations; these results do not validate predictions for a
Liquid Tree reactor. Growth-rate analyses also report weaker LOEO generalization
for some targets. See `summary.md` and the Phase 5–7 reports for methods and
metrics.

### Dashboard formula estimate

`POST /api/predict` returns an experimental formula-based estimate. It does not
load the offline Random Forest, and no validation metrics or confidence values
are claimed for the formula.

### YOLOv8 Nano microscopy proof of concept

The active local checkpoint is
`models/phase9c_yolo/train_20epochs/weights/best.pt` (5.96 MB; SHA-256
`a3d69c16a3a9ca21d485d8e2648fe0db05c633195b53dfd8833a014a26242c41`). It is a
project training output initialized from the local `models/yolov8n.pt` base
weights (6.25 MB). Class 0 is `chlorella_cell`; class 1 is `cluster_noise` and
is excluded from individual-cell counts.

On the fixed 93-image validation split, the report records class-0 count MAE
2.247 cells/image, RMSE 4.666, signed bias +0.333 (prediction minus ground
truth), precision 0.781 and recall 0.808 at confidence 0.25 and IoU 0.50. The
all-class mAP50 is 0.4698 and mAP50–95 is 0.2189. The 20-epoch checkpoint was
tentatively preferred for typical count error; its RMSE is worse than the pilot
checkpoint’s. This small validation comparison is a microscopy proof of concept,
not independent external validation or live Liquid Tree hardware performance.
See `reports/phase10_microscopy_checkpoint_comparison.md` for settings,
matching procedure, limitations, and the pilot comparison.

The checkpoints and base weights remain local pending confirmation of their
redistribution terms and source provenance. They are not downloaded by the
setup commands below. If supplied through an approved project archive, verify
the selected checkpoint SHA-256 above before use. The server can still serve the
dashboard without it; microscopy inference will be unavailable.

## Setup (Windows PowerShell)

Use Python 3.12 and create a virtual environment from the project root:

```powershell
cd C:\4algae
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

The checked local environment used Python 3.12.4, PyTorch 2.14.1 (CPU), and
Ultralytics 8.4.174, among other packages. PyTorch installation can depend on
the target platform and accelerator; use the appropriate official PyTorch wheel
if the generic requirement does not match the machine. Dependencies are not
automatically reinstalled or upgraded by running the application.

Start the local server:

```powershell
.\.venv\Scripts\python.exe api\server.py --port 8050
```

Open <http://127.0.0.1:8050/index.html>. The server binds to loopback. Stop it
with **Ctrl+C** in the server terminal.

## Tests and syntax checks

From the project root:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m py_compile api\server.py api\service.py tests\test_microscopy_integrity.py
node --check dashboard\app.js
```

The Python tests cover microscopy success, empty detections, unavailable weights,
inference errors, prediction/annotation separation, density calibration status,
and selected-checkpoint configuration.
